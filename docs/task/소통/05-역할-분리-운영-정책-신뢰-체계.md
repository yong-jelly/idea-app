# Task 05. 역할 분리, 운영 정책, 신뢰 체계 설계

## 목적

소통 기능이 단발성 UI 개선에 그치지 않도록, 역할 분리와 운영 규칙, 응답 기준, 신뢰 지표를 함께 정의한다.

---

## 범위

- 사용자 액션과 관리자 액션 분리
- 응답 정책
- 상태 관리 정책
- 모더레이션 기준
- 신뢰 지표 정의

---

## 설계 원칙

### 원칙 1. 참여 화면은 사용자 중심으로 보여야 한다

#### 필요한 콘셉

- 관리자 도구가 전면에 보이면 사용자는 자신이 손님처럼 느껴진다.
- 기본 화면은 "참여할 수 있는 공간"처럼 인지되어야 한다.

#### 필요한 아이디어

- 사용자 액션과 관리자 액션 분리
- 관리자 메뉴는 더보기 또는 편집 모드로 숨김

#### 개선 항목

- 화면 내 권한 기반 노출 재정의
- 사용자 기본 시점에서 운영 도구 비중 축소
- 관리자용 상태 변경/답변/병합 UI 분리

### 원칙 2. 응답은 기능이 아니라 약속이다

#### 필요한 콘셉

- 소통 품질은 화면 디자인만으로 만들어지지 않는다.
- 응답 시간과 상태 관리 기준이 있어야 사용자가 신뢰한다.

#### 필요한 아이디어

- 24시간 내 1차 응답 권장
- 7일 내 요청 상태 분류
- 보류/중복 사유 명시

#### 개선 항목

- 응답 SLA 정의
- 상태 변경 기준 문서화
- 팀 탭 또는 대화 탭에 정책 요약 노출

### 원칙 3. 부정적 의견도 시스템 안에서 다뤄야 한다

#### 필요한 콘셉

- 진짜 커뮤니티는 좋은 반응만 다루지 않는다.
- 부정적 피드백도 삭제보다 응답과 정리로 처리해야 신뢰가 생긴다.

#### 필요한 아이디어

- 신고 정책
- 광고/비방/개인정보 기준
- 관리자 대응 프로토콜

#### 개선 항목

- 모더레이션 가이드 정의
- 신고 후 처리 상태 안내
- 운영자 대응 일관성 확보

### 원칙 4. 신뢰 지표는 보여주기보다 측정 가능해야 한다

#### 필요한 콘셉

- 응답률, 첫 응답 시간, 해결 건수는 마케팅 수치가 아니라 운영 건강도 지표다.
- 내부 정의 없이 외부 노출하면 신뢰를 해칠 수 있다.

#### 필요한 아이디어

- 첫 응답 시간
- 최근 30일 응답률
- 반영/출시 연결률
- 미답변 비율

#### 개선 항목

- 지표 계산 기준 정의
- 노출 기준과 비노출 기준 정의
- 프로젝트 단위와 플랫폼 단위 측정 분리

---

## 완료 기준

- 사용자와 관리자 액션이 명확히 구분된다.
- 응답 및 상태 관리 기준이 문서화된다.
- 모더레이션 기준이 정리된다.
- 외부 노출 가능한 신뢰 지표의 산식과 조건이 정해진다.
