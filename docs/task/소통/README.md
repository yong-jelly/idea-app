# 프로젝트 페이지 소통 개선 Task 분해

## 문서 목적

이 디렉토리는 `docs/task/프로젝트-유저-소통-개선.md`를 실행 가능한 작업 단위로 분리한 문서 모음입니다.

현재 개선 범위는 **프로젝트 페이지**입니다.  
메인페이지(피드) 개선은 프로젝트 페이지 소통 구조가 정리된 이후 다음 단계로 진행합니다.

---

## 기본 전제

- 지금 손보는 대상은 `/project/[id]` 상세페이지다.
- 목표는 프로젝트 페이지를 `소개 화면`에서 `소통 운영 화면`으로 전환하는 것이다.
- 기능 추가보다 중요한 것은 **행동 유도, 관계 형성, 신뢰 구축**이다.
- 각 Task는 `UI/UX 설계자`, `미니멀리스트 디자이너`, `소통 및 심리학 전문가` 관점을 동시에 반영한다.
- 모든 개선은 `UI/UX 선행`을 원칙으로 한다.
- API 개선 및 연동은 UI/UX 구조가 확정된 뒤 점진적으로 붙인다.

---

## 실행 방침

### 1. UI/UX를 먼저 고정한다

- 화면 구조
- 행동 우선순위
- 카피
- 시각적 위계
- 모바일 진입 흐름

위 항목이 먼저 정리되어야, 이후 API가 어떤 데이터를 어떤 우선순위로 제공해야 하는지 자연스럽게 정의된다.

### 2. API는 UI에 종속적으로 점진 개선한다

- 초기 단계에서는 기존 데이터와 임시 문구, 조건부 노출로도 UI 검증을 시작할 수 있다.
- 신뢰 지표, 팀 노트, 요청 보드 상태 같은 항목은 UI가 자리를 잡은 뒤 API를 순차적으로 연결한다.
- 즉, 이번 개선은 `백엔드 주도 기능 추가`가 아니라 `프론트 경험 설계 -> 필요한 데이터 정의 -> 점진 연동` 순서로 간다.

## 공통 설계 원칙

### 원칙 1. 행동 우선

사용자는 프로젝트를 이해한 직후 곧바로 말을 걸 수 있어야 한다.  
정보 탐색보다 참여 진입이 먼저 보여야 한다.

### 원칙 2. 미니멀한 위계

미니멀리즘은 요소 삭제가 아니라 우선순위 정리다.  
핵심 CTA와 신뢰 신호를 제외한 보조 액션은 시각적 비중을 낮춰야 한다.

### 원칙 3. 심리적 안전감

사용자는 안전하다고 느껴야 의견을 남긴다.  
톤, 상태, 답변 예측 가능성, 운영 정책이 이를 뒷받침해야 한다.

### 원칙 4. 기여 효능감

의견은 사라지면 안 된다.  
질문, 요청, 팀 노트, 업데이트가 연결되어 "내 의견이 반영될 수 있다"는 감각을 만들어야 한다.

### 원칙 5. 역할 분리

사용자와 관리자/팀의 액션은 같은 화면 안에 있어도 목적과 레벨이 분리되어야 한다.  
사용자는 참여 공간으로, 팀은 운영 공간으로 인지해야 한다.

## 우선순위 기준

### `P0` 즉시 착수

- 사용자가 프로젝트 페이지에서 "어떻게 말을 걸어야 하는지"를 이해하게 만드는 작업
- 구현 전후 차이가 가장 빠르게 체감되는 영역
- 프로젝트 페이지의 소통 정체성을 바꾸는 최소 조건

### `P1` 구조 안정화

- 사용자 의견이 사라지지 않고 운영 가능한 흐름으로 남게 만드는 작업
- 팀의 목소리, 요청 상태, 운영 정책이 함께 정리되는 단계
- 프로젝트 페이지를 일시적 이벤트가 아니라 반복 가능한 소통 공간으로 만드는 영역

### `P2` 확장 준비

- 모바일 우선성, 적용 순서, 메인 피드 확장을 위한 연결 설계
- 직접적인 UI 변화보다 전체 실행 전략과 다음 단계 전환을 정리하는 영역

## 메인 피드 개선으로 넘어가기 위한 게이트

프로젝트 페이지 개선 이후 메인 피드 개선에 착수하려면 아래 조건이 먼저 정리되어야 한다.

- `P0` Task가 완료되어 프로젝트 상세의 소통 진입 구조가 명확해질 것
- `Task 03` 또는 `Task 04`를 통해 피드에서 노출할 소통 신호가 정의될 것
- `Task 05`를 통해 응답률, 첫 응답 시간, 반영 연결률 등 핵심 지표 정의가 끝날 것
- 모바일 기준 참여 흐름이 최소 수준으로 검증될 것

이 게이트가 충족되어야 메인 피드가 단순 콘텐츠 목록이 아니라,  
**"지금 가장 살아 있는 프로젝트 대화"를 발견시키는 구조**로 확장될 수 있다.

---

## 실무 적용 메모

- 기획 리뷰는 `Task 01 -> 02 -> 03` 순으로 진행하는 것이 가장 효율적이다.
- 디자인 리뷰는 `Task 01`, `Task 04`, `Task 06`을 묶어 보는 것이 좋다.
- 운영/정책 리뷰는 `Task 03`, `Task 05`를 함께 검토해야 한다.
- 메인 피드 개선 기획은 프로젝트 페이지 `P0/P1` 구조가 고정된 뒤 시작한다.

---

## 다음 단계 메모

프로젝트 페이지 개선이 완료되면, 메인 피드 개선은 아래 질문을 중심으로 이어져야 한다.

- 어떤 프로젝트가 지금 활발히 대화 중인지 어떻게 보여줄 것인가
- 어떤 팀이 응답을 잘하는지 어떻게 발견하게 할 것인가
- 어떤 요청과 업데이트가 실제로 살아 움직이는지 피드에서 어떻게 노출할 것인가

즉, 메인 피드는 프로젝트 페이지의 소통 구조를 발견 가능한 흐름으로 확장하는 단계가 되어야 한다.
