# Task 06. 모바일 우선 레이아웃과 단계별 적용 계획

## 목적

프로젝트 페이지 소통 개선안을 실제 적용 가능한 순서로 정리하고, 모바일 우선 관점에서 핵심 경험이 유지되도록 설계한다.

---

## 범위

- 모바일 우선 레이아웃 원칙
- 데스크톱 확장 원칙
- 단계별 적용 순서
- 프로젝트 페이지 개선 완료 후 메인 피드 개선 연결 메모

---

## 설계 원칙

### 원칙 1. 모바일에서 성립하지 않으면 소통 구조가 아니다

#### 필요한 콘셉

- 프로젝트 페이지의 소통 진입은 모바일에서 더 자주 발생한다.
- 따라서 대화, 요청, 팀 노트 진입은 모바일 기준으로 먼저 검증되어야 한다.

#### 필요한 아이디어

- 하단 고정 CTA 또는 FAB
- 유형 선택 바텀시트
- 탭보다 짧은 액션 우선

#### 개선 항목

- 모바일에서 `의견 남기기` CTA 고정
- 대화/요청/팀 노트 진입을 한 손 동선 기준으로 재배치
- 좋아요/저장/공유는 보조 영역으로 이동

### 원칙 2. 데스크톱은 정보량이 아니라 확장성으로 설계한다

#### 필요한 콘셉

- 데스크톱은 더 많은 정보를 보여줄 수 있지만, 그 자체가 더 나은 UX를 의미하진 않는다.
- 메인 컬럼과 보조 컬럼의 역할이 분리되어야 한다.

#### 필요한 아이디어

- 좌측 본문, 우측 신뢰/CTA 패널
- 최근 해결 요청
- 팀 노트 하이라이트

#### 개선 항목

- 사이드 패널에 CTA와 신뢰 지표 집중
- 본문 컬럼은 현재 탭 콘텐츠에 집중
- 데스크톱에서도 메인 행동 수를 제한

### 원칙 3. 실행은 한 번에 바꾸지 말고 심리적 변화부터 만든다

#### 필요한 콘셉

- 소통 구조는 화면보다 인식 변화가 중요하다.
- 따라서 가장 먼저 바꿔야 하는 것은 사용자가 "여기서 대화할 수 있다"고 느끼게 만드는 부분이다.

#### 필요한 아이디어

- Phase 1: CTA와 기본 대화 진입
- Phase 2: 요청 보드와 상태 체계
- Phase 3: 팀 노트, 알림, 측정 고도화

#### 개선 항목

- 첫 단계에서 상단 CTA와 대화 탭 우선 적용
- 두 번째 단계에서 구조화 피드백과 상태 관리 적용
- 세 번째 단계에서 장기 재방문 기능 확장

### 원칙 4. 프로젝트 페이지 개선은 메인 피드 개선의 기반이다

#### 필요한 콘셉

- 메인 피드는 프로젝트 페이지에서 벌어지는 대화를 더 잘 발견하게 만드는 층위다.
- 상세가 정리되지 않으면 피드 개선도 피상적이 된다.

#### 필요한 아이디어

- 활발한 대화 프로젝트
- 응답이 빠른 팀
- 최근 반영된 요청
- 팀 노트가 활발한 프로젝트

#### 개선 항목

- 프로젝트 페이지에서 사용할 핵심 지표 정의 선행
- 이후 메인 피드에서 어떤 소통 신호를 노출할지 메모 축적
- 피드 개선은 별도 트랙으로 분리하되 종속 관계 명시

---

## 권장 단계

### 1단계

- Hero 재구성
- 핵심 CTA 정리
- `대화` 탭 기본화
- 모바일 작성 진입 단순화

### 2단계

- 요청 보드 도입
- 상태 관리
- 업데이트 연결
- 관리자/사용자 역할 분리

### 3단계

- 팀 노트 정식 도입 또는 고도화
- 구독/알림
- 소통 건강도 측정

### 4단계

- 메인 피드 개선 착수
- 프로젝트 상세에서 검증된 소통 신호를 피드 노출에 반영

---

## 완료 기준

- 모바일에서 핵심 참여 흐름이 짧고 명확하다.
- 데스크톱과 모바일의 우선순위가 일관된다.
- 개선 순서가 기능 단위가 아니라 경험 단위로 정리된다.
- 메인 피드 개선이 다음 단계로 자연스럽게 연결된다.
