# Task 01. 상단 진입 구조 재설계

## 목적

프로젝트 상세에 들어온 사용자가 첫 5~10초 안에

- 이 프로젝트가 무엇인지 이해하고
- 어디서 팀과 대화할 수 있는지 알고
- 바로 행동할 수 있게 만드는 상단 구조를 설계한다.

---

## 범위

- Hero 영역
- 핵심 CTA
- 신뢰 지표
- 좋아요/저장/공유 등 보조 액션의 위계

---

## 실행 원칙

### UI/UX 선행

이 Task는 전체 소통 개선의 출발점이므로, 먼저 상단 경험의 구조와 카피, 위계를 UI/UX 차원에서 확정한다.

- 어떤 버튼이 가장 먼저 보여야 하는가
- 어떤 정보가 신뢰를 만드는가
- 어떤 액션이 보조로 내려가야 하는가
- 모바일에서 무엇이 항상 보여야 하는가

이 질문에 대한 답을 먼저 고정한 뒤 API 연동은 점진적으로 따라온다.

### API 점진 연동

초기 구현에서는 기존 프로젝트 데이터와 로컬/임시 상태, 조건부 문구만으로도 상단 구조를 먼저 검증할 수 있다.

예:

- `최근 답변 시간`이 아직 없다면 임시 숨김 또는 준비중 처리
- `응답률`이 아직 계산되지 않으면 미노출
- `팀 노트 보기`가 아직 없다면 CTA는 비활성 또는 다음 단계 연결

즉, 이 Task의 1차 완료 기준은 API 완결이 아니라 **상단 경험의 방향성과 위계가 실제 화면에서 검증되는 것**이다.

---

## 현재 화면 기준 진단

현재 코드 기준으로 상단은 아래 문제가 있다.

- 기본 탭이 `overview`라 소통보다 정보 소비가 먼저 온다.
- `커뮤니티 참여` CTA와 좋아요/저장/링크 액션이 같은 레벨에서 병렬 배치된다.
- Hero 안에서 메인 행동과 보조 행동의 위계가 충분히 벌어지지 않는다.
- 신뢰 지표가 상단에서 거의 보이지 않아 사용자가 "답을 받을 수 있는 곳인지" 빠르게 판단하기 어렵다.

따라서 상단 구조는 단순 스타일 조정이 아니라, **행동 우선순위 재배치** 관점으로 접근해야 한다.

---

## 설계 원칙

### 원칙 1. 첫 행동은 하나처럼 보여야 한다

#### 필요한 콘셉

- 상단은 소개 영역이 아니라 `행동 출발점`이어야 한다.
- 사용자는 "커뮤니티가 있나?"보다 "지금 무엇을 할 수 있나?"를 먼저 알아야 한다.

#### 필요한 아이디어

- 메인 CTA를 `의견 남기기`로 명확히 정의
- 보조 CTA를 `요청 보드 보기`, `팀 노트 보기`로 분리
- `커뮤니티 참여` 같은 추상 문구는 지양

#### 개선 항목

- 상단 CTA를 1개 메인, 1~2개 보조로 재정렬
- CTA 카피를 행동 중심 동사형으로 통일
- CTA 클릭 시 유형 선택 바텀시트/모달 연결

### 원칙 2. 미니멀한 위계가 필요하다

#### 필요한 콘셉

- 사용자의 주 행동은 저장이나 공유가 아니라 참여다.
- 보조 액션은 존재해도 되지만 메인 행동을 방해하면 안 된다.

#### 필요한 아이디어

- 좋아요/저장/링크는 아이콘형 보조 액션으로 축소
- 프로젝트명, 한 줄 소개, 핵심 CTA, 신뢰 지표만 Hero의 중심축으로 사용

#### 개선 항목

- 보조 액션의 크기/색상/위치를 메인 CTA보다 한 단계 낮춤
- 상단에 카드나 박스가 많다면 단일 구조로 통합
- 데스크톱과 모바일 모두 CTA 중심 시선 흐름 확보

### 원칙 3. 신뢰는 행동 전에 보여야 한다

#### 필요한 콘셉

- 사용자는 말하기 전에 "답을 들을 수 있을지"를 먼저 판단한다.
- 신뢰 지표는 결과 화면이 아니라 진입 화면에 있어야 한다.

#### 필요한 아이디어

- `최근 답변 시간`
- `최근 30일 응답률`
- `반영/해결 건수`
- `최근 업데이트` 배지

#### 개선 항목

- Hero에 최소 2~3개의 신뢰 신호 삽입
- 숫자는 과장보다 해석 가능한 짧은 문장으로 제공
- 업데이트와 응답 기록이 있을 때만 활성 노출

### 원칙 4. 심리적 압박보다 초대감이 중요하다

#### 필요한 콘셉

- 참여는 요청이 아니라 초대처럼 느껴져야 한다.
- "평가해달라"보다 "도와달라"는 톤이 더 부드럽다.

#### 필요한 아이디어

- `불편한 점 알려주기`
- `팀과 대화 시작하기`
- `이 프로젝트 개선에 참여하기`

#### 개선 항목

- Hero 카피 전반을 초대형 문체로 정리
- 부정 평가 유도 대신 구체적 도움 요청 중심으로 전환

---

## 1차 구현 범위 (UI/UX 우선)

### 1. Hero 정보 구조 재배치

- 프로젝트명
- 한 줄 소개
- 대표 링크
- 메인 CTA
- 보조 CTA
- 보조 액션

### 2. CTA 위계 재정의

- 메인 CTA: `의견 남기기`
- 보조 CTA: `요청 보드 보기`, `팀 노트 보기`
- 보조 액션: `좋아요`, `저장`, `링크 공유`

### 3. 신뢰 지표 슬롯 확보

- 실제 데이터 유무와 무관하게 Hero 안에 신뢰 지표 영역을 먼저 설계
- 1차에서는 더미 또는 조건부 미노출 허용

### 4. 모바일 우선 진입 구조 확정

- 스크롤 중에도 메인 CTA가 묻히지 않게 설계
- 버튼 수를 줄이고 유형 선택은 2단계로 미룬다

---

## 2차 구현 범위 (API 점진 연동)

### 연동 후보 데이터

- 최근 답변 시간
- 최근 30일 응답률
- 반영/해결 건수
- 최근 업데이트 여부

### 연동 원칙

- 데이터가 없으면 숨기거나 대체 문구 사용
- 지표는 과장하지 않고 실제 계산 기준이 정의된 것만 노출
- UI에서 먼저 필요성이 검증된 항목부터 순차 연결

---

## 즉시 산출물

### 산출물 1. Hero 와이어 구조

- 데스크톱용 상단 정보 블록
- 모바일용 상단 정보 블록
- CTA/보조 액션/신뢰 지표 우선순위 정의

### 산출물 2. 카피 세트

- 메인 CTA 후보
- 보조 CTA 후보
- 신뢰 지표 라벨 후보
- 빈 상태 또는 미노출 대체 문구

### 산출물 3. 구현 체크리스트

- 기존 상단 컴포넌트에서 제거/축소할 요소
- 1차 UI-only로 가능한 변경
- 2차 API 연동이 필요한 요소

## V1 화면 제안

### 데스크톱 Hero

#### 1열: 프로젝트 정체성

- 프로젝트 썸네일
- 프로젝트명
- 한 줄 소개
- 대표 링크

#### 2열: 참여 유도

- 메인 CTA: `의견 남기기`
- 보조 CTA 1: `요청 보드 보기`
- 보조 CTA 2: `팀 노트 보기`

#### 3열: 신뢰와 보조 액션

- 신뢰 지표 2~3개
- 좋아요
- 저장
- 링크 공유

핵심은 지금처럼 모든 액션이 한 줄에서 경쟁하는 구조가 아니라,  
`정체성 -> 행동 -> 신뢰/보조 액션` 순으로 시선이 흐르게 만드는 것이다.

### 모바일 Hero

#### 1단

- 프로젝트명
- 한 줄 소개

#### 2단

- 메인 CTA: `의견 남기기`

#### 3단

- 보조 액션: 좋아요, 저장, 링크

#### 4단

- 대표 링크
- 신뢰 지표 1~2개

모바일에서는 버튼 수를 줄여 `한 번에 하나의 결심`만 하게 해야 한다.  
따라서 메인 CTA 1개를 우선 노출하고, 나머지는 보조 층위로 내린다.

## UI-only 최소 변경안

API 변경 없이도 바로 시작할 수 있는 1차 적용안은 아래와 같다.

### 1. CTA 라벨 변경

- `커뮤니티 참여` -> `의견 남기기`
- `커뮤니티 참여하기` -> `팀과 대화하기` 또는 `의견 남기기`

### 2. 액션 위계 재배치

- 좋아요/저장/링크를 메인 CTA 오른쪽 병렬 경쟁 구조에서 분리
- 보조 액션 묶음을 별도 row 또는 하단 블록으로 이동

### 3. 신뢰 지표 슬롯만 먼저 확보

- 실제 데이터가 없더라도 지표 영역 자리부터 만든다
- 초기에는 아래 중 하나를 사용
  - 미노출
  - `응답 지표 준비 중`
  - 최근 업데이트 유무만 우선 노출

### 4. 기존 라우트 재활용

- 메인 CTA는 우선 기존 `/project/:id/community`로 연결
- 즉, 1차는 정보 구조와 카피를 바꾸고, 목적지는 기존 라우트를 재사용한다

이 방식이면 API나 정보 구조 전체를 뜯지 않고도,  
사용자 인식은 먼저 "이 페이지는 소통이 중심이다"로 바뀌게 만들 수 있다.

## 프론트 구현 체크포인트

### 체크포인트 1

- `overview` 기본 진입과 무관하게 Hero 상단에서 소통 CTA가 먼저 보이는가

### 체크포인트 2

- 메인 CTA가 좋아요/저장/공유보다 시각적으로 더 강한가

### 체크포인트 3

- 모바일에서 첫 화면 스크린샷만 봐도 "여기서 말할 수 있구나"가 전달되는가

### 체크포인트 4

- 신뢰 지표가 없더라도 UI가 비어 보이지 않고 자연스러운가

---

## 착수 순서

1. 현재 Hero의 액션 위계를 재정의한다.
2. 데스크톱/모바일 Hero 와이어 구조를 문서로 확정한다.
3. CTA/카피 후보를 정한다.
4. UI-only 범위로 먼저 화면을 수정한다.
5. 이후 신뢰 지표와 보조 CTA를 API와 점진 연동한다.

---

## 완료 기준

- 상단만 보고 사용자가 첫 행동을 추정할 수 있다.
- 메인 CTA와 보조 액션의 우선순위가 명확하다.
- 신뢰 지표가 참여 전에 노출된다.
- 모바일에서도 CTA가 스크롤에 묻히지 않는다.
- API가 완전하지 않아도 UI 구조 자체는 먼저 검증 가능하다.
