# Task 02. 대화 탭과 참여 진입 설계

## 목적

프로젝트 페이지에서 사용자가 가장 부담 없이 처음 말을 걸 수 있는 기본 대화 공간을 설계한다.

---

## 범위

- `대화` 탭 기본화
- 빠른 작성 박스
- 유형 선택
- 필터/정렬
- 기본 스레드 카드 구조

---

## 설계 원칙

### 원칙 1. 대화는 가장 먼저 보여야 한다

#### 필요한 콘셉

- 프로젝트 상세의 첫 탭은 정보보다 관계 형성에 유리해야 한다.
- 사용자는 먼저 말할 수 있어야 이후 개요와 팀 정보도 더 깊게 본다.

#### 필요한 아이디어

- `대화`를 기본 탭으로 설정
- 상단에 빠른 작성 박스 배치
- 팀 답변이 있는 스레드를 초기에 일부 노출

#### 개선 항목

- 첫 진입 탭을 `개요`에서 `대화`로 전환
- 대화 탭 내 작성 진입을 스크롤 상단에 고정
- 미답변/답변완료 구분 필터 추가

### 원칙 2. 참여 언어를 시스템이 제공해야 한다

#### 필요한 콘셉

- 사용자는 무엇을 어떻게 써야 할지 모르면 침묵한다.
- 입력창보다 입력 유형이 먼저 제시될 때 참여 마찰이 크게 줄어든다.

#### 필요한 아이디어

- `질문`
- `버그 제보`
- `기능 요청`
- `개선 아이디어`
- `자유 의견`

#### 개선 항목

- 작성 시 유형 칩 선택 기본 제공
- 유형별 플레이스홀더/템플릿 차등 적용
- 로그인 유도 시 작성 의도 보존

### 원칙 3. 카드 구조는 읽기보다 반응을 돕는 방향이어야 한다

#### 필요한 콘셉

- 대화 카드가 너무 무거우면 피드처럼 흘러가지 않는다.
- 사용자는 빠르게 훑고, 필요한 곳에 반응할 수 있어야 한다.

#### 필요한 아이디어

- 제목 또는 첫 문장 중심의 카드
- 팀 답변 여부 표시
- 공감 수, 댓글 수, 상태 표시

#### 개선 항목

- 카드 높이와 정보량 최소화
- 답변 완료 스레드와 미답변 스레드를 쉽게 식별 가능하게 설계
- 카드 클릭 없이도 반응 상태를 파악할 수 있게 함

### 원칙 4. 심리적 안전감을 먼저 만든다

#### 필요한 콘셉

- 사용자는 비난받을까 걱정하면 말하지 않는다.
- 대화 탭은 커뮤니티 게시판보다 `안전한 질문 공간`처럼 보여야 한다.

#### 필요한 아이디어

- 빈 상태에서 질문 예시 제공
- 첫 작성 가이드
- 팀의 응답 기대치 노출

#### 개선 항목

- `무엇이 불편했나요?`, `궁금한 점을 편하게 물어보세요` 같은 초대형 문구 사용
- 신규 사용자용 예시 질문 노출
- 팀 응답 SLA를 대화 탭 안에서 안내

---

## 완료 기준

- 사용자가 1회 클릭 또는 2단계 이내로 글쓰기를 시작할 수 있다.
- 어떤 종류의 글을 써야 하는지 UI가 먼저 안내한다.
- 대화 리스트를 보는 것만으로 팀이 응답하는 공간인지 느껴진다.
- 초보 사용자도 "여기서 질문해도 된다"는 인상을 받는다.
